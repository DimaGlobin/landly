# Database Migrations

## Структура миграций

Миграции организованы по функциональному принципу:

1. **001_init_schema.sql** - Базовая схема БД
   - Все основные таблицы: users, projects, integrations, publish_targets, generation_sessions, analytics_events, project_schema_versions
   - Все необходимые поля и индексы включены сразу
   - UNIQUE constraints для обеспечения целостности данных

2. **002_generation_messages.sql** - Функционал чата генерации
   - Таблица generation_messages для хранения истории чата
   - Индексы для оптимизации запросов

3. **003_optimize_schema.sql** - Оптимизация и очистка
   - Удаление неиспользуемых таблиц (pages, blocks)
   - Исправление несоответствий для старых БД
   - Добавление недостающих constraints и индексов
   - Безопасна для применения на существующих БД

## Применение миграций

### Локальная разработка
```bash
make migrate
```

### Production
```bash
docker-compose -f deploy/docker/docker-compose.yml exec backend /app/migrate up
```

## Генерация checksums

После создания или изменения миграций необходимо обновить checksums:

```bash
make migration-checksums
```

Это автоматически сгенерирует файл `checksums.sha256` с хешами всех миграций.

## Валидация checksums

CI автоматически проверяет checksums при каждом коммите:

```bash
make migration-validate
```

## Важные правила

1. **НЕ изменяйте уже примененные миграции** - это сломает checksums и может привести к проблемам в production
2. **Создавайте новые миграции** вместо изменения существующих
3. **Группируйте изменения по смыслу** - не создавайте мелкие миграции для одного столбца
4. **Всегда обновляйте checksums** после создания новой миграции

## Откат миграций

Для отката последней миграции:

```bash
make migrate-down
```

**Внимание:** Откат миграций в production должен выполняться с особой осторожностью и только при необходимости.
